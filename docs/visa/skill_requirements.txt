职位类型一：ETL管道构建专家
=====================================

一、核心经验要求
=====================================

1. 必备工作经验（按优先级排序）

   1.1 数据处理实战经验（3-5年）
   具体描述：
   • 设计和实现端到端ETL管道的经验
   • 处理TB级数据量的实际项目经验
   • 从0到1构建数据处理系统的完整经验
   • 多种数据源整合的实战经验（数据库、API、文件等）
   • 数据质量问题和解决方案的经验

   证明方式：
   ✅ 项目案例：详细描述2-3个完整的ETL项目
   ✅ 技术问题：列出遇到的具体技术挑战和解决方案
   ✅ 性能数据：量化改进效果（如处理时间从4小时降至30分钟）
   ✅ 工具使用：具体使用过的ETL工具和框架
   ✅ 系统规模：处理数据量、用户规模、业务规模

   1.2 数据仓库设计和实施经验（2-4年）
   具体描述：
   • 数据仓库架构设计经验
   • 星型模型和雪花模型实际应用
   • OLAP vs OLTP架构选择经验
   • 数据建模和规范化经验
   • 数据分区、索引优化经验
   • 历史数据处理和归档经验

   证明方式：
   ✅ 架构设计：提供数据仓库架构图和设计文档
   ✅ 数据模型：展示实际设计的星型/雪花模型
   ✅ 性能优化：查询性能改进的具体案例
   ✅ 存储优化：存储成本降低的实际数据
   ✅ 项目规模：涉及的业务域、数据量、用户数

   1.3 SQL和数据库优化经验（3-5年）
   具体描述：
   • 复杂SQL查询编写和优化
   • 存储过程、函数、触发器开发
   • 数据库性能调优经验
   • 索引策略和优化
   • 查询执行计划分析
   • 数据库维护和监控

   证明方式：
   ✅ SQL案例：复杂SQL查询的实际示例
   ✅ 性能数据：查询优化前后的对比数据
   ✅ 索引设计：具体的索引策略和效果
   ✅ 故障处理：数据库性能问题的解决案例
   ✅ 工具使用：使用的数据库管理工具

二、核心技能要求
=====================================

2. 技术技能（按重要程度排序）

   2.1 Python数据处理技能（精通级别）
   详细要求：
   ✅ Pandas：高级使用（groupby, merge, 时间序列处理）
   ✅ NumPy：数值计算和数组操作
   ✅ 数据清洗：处理缺失值、异常值、重复数据
   ✅ 数据转换：数据格式转换、类型转换
   ✅ 性能优化：内存优化、并行处理

   实际应用案例：
   • 使用Pandas处理100GB+数据集
   • 实现复杂的数据转换逻辑
   • 优化数据加载性能（如从4小时降至30分钟）
   • 处理不完整、不一致的数据源

   2.2 Apache Spark技能（熟练级别）
   详细要求：
   ✅ PySpark：DataFrame API和Spark SQL
   ✅ Spark Core：RDD操作（了解即可）
   ✅ Spark Streaming：流数据处理基础
   ✅ 性能优化：分区、缓存、广播变量
   ✅ 集群管理：YARN、Standalone模式

   实际应用案例：
   • 使用Spark处理TB级数据
   • 实现增量数据处理
   • 优化Spark作业性能
   • 解决数据倾斜问题

   2.3 ETL工具和框架（熟练级别）
   详细要求：
   ✅ Apache Airflow：DAG设计、Operator开发
   ✅ 数据集成：Kettle、Talend（了解）
   ✅ 数据质量：Great Expectations、Deequ
   ✅ 版本控制：ETL脚本的版本管理
   ✅ CI/CD：ETL流程的自动化部署

   实际应用案例：
   • 设计复杂的Airflow DAG
   • 开发自定义Airflow Operator
   • 实现数据质量检查流程
   • 建立ETL监控和告警

   2.4 数据库技能（熟练级别）
   详细要求：
   ✅ 关系数据库：PostgreSQL、MySQL、Oracle
   ✅ NoSQL数据库：MongoDB、Redis、Cassandra
   ✅ 数据仓库：Snowflake、Redshift、BigQuery
   ✅ 查询优化：索引、执行计划分析
   ✅ 数据建模：规范化、反规范化

   实际应用案例：
   • 设计数据库schema和索引
   • 优化慢查询性能
   • 处理数据一致性问题
   • 实施数据分区策略
